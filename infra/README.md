# Infrastructure (AWS, Terraform)

One command from nothing to running: VPC → RDS Postgres 16 → ECS Fargate (ARM64) → ALB,
with the DB password generated by Terraform and stored in SSM (never in a task definition).

```bash
cd infra
terraform init
terraform apply                       # ~8 min, most of it RDS

# Build and push the image (ARM64 — native on Apple silicon, Graviton in the cloud):
aws ecr get-login-password --region us-east-1 \
  | docker login --username AWS --password-stdin "$(terraform output -raw ecr_repository_url | cut -d/ -f1)"
docker build -t "$(terraform output -raw ecr_repository_url):latest" ..
docker push "$(terraform output -raw ecr_repository_url):latest"
aws ecs update-service --cluster seat-reservation --service seat-reservation \
  --force-new-deployment --region us-east-1 > /dev/null

terraform output app_url              # open it
```

Costs roughly **$1–2/day** while up (Fargate 0.5 vCPU + db.t4g.micro + ALB). Tear down:

```bash
terraform destroy
```

Deliberate demo-stack shortcuts, called out rather than hidden: HTTP only (no ACM cert/domain),
single-AZ RDS with no backups, tasks in public subnets instead of a ~$32/mo NAT gateway, no
remote Terraform state. `app_count = 2` runs the multi-instance no-double-sell guarantee in the
cloud (correctness is instance-agnostic; only SSE liveness is per-instance — a documented cut).
